# v4.12.6 — Reconciliation v3 (trade-link expected vs actual)

## Roadmap line
trade_links (+pnl) → trade_recon_v3 (deterministic diff + taxonomy)

## What changed
- Added recon store + schema: `src/storage/sqlite_store_recon.py` (`trade_recon_v3`)
- Added reconciliation engine: `src/reconcile/reconcile_v3.py`
- Added runner: `src/runners/reconcile_v3.py`
- Emits `shadow_snapshots(kind='recon_v3')`
- Added mechanisms doc: `docs/MECHANISMS_v4.12.6_reconciliation_v3.md`

## Mechanism (short)
- Pull expected entry/exit timestamps + prices from latest model trace (ENTRY + last EXIT/TP/SL)
- Pull actual entry/exit WAP + timestamps from latest trade_link
- Compute adverse slippage in pips (entry, exit, total) with stable sign convention
- Compute latency in seconds (actual - expected)
- Assign stable status/code taxonomy (OK/WARN/ERROR) suitable for downstream gating

## Run (operator path)
```bash
python -m src.runners.reconcile_v3   --db ./journal/trader.db   --signal-idem-key <KEY>   --slip-warn-pips 1   --slip-error-pips 5   --overwrite
```

## Artifacts (what to expect)
- tables:
  - `trade_recon_v3`
- snapshots:
  - `recon_v3`

## Why it matters
- This is the “truth serum” step: you can’t gate, report, or improve execution without a stable expected-vs-actual diff.

## Caveats
- Trace must include expected prices for ENTRY and EXIT (or TP/SL) events.
- Pip size is required; we fall back to `symbol_meta` if trade_link payload lacks it.
